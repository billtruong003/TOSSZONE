## 1. Bugs found and fixed by this testing (not just "ran once and it worked")

1. **`LayerMask.NameToLayer` in a static field initializer** — `HitscanGun`'s `_hitMask` was a
   `static readonly` field computed at type-init time. Unity throws
   `UnityException: NameToLayer is not allowed to be called from a MonoBehaviour constructor (or instance
   field initializer)` — confirmed via Play Mode console. Fixed: lazy-computed on first call (`HitMask()`
   method + `_hitMaskReady` flag) instead of a field initializer.
2. **`GunFeedback.OnEnable` subscribed to `Bill.Events` unconditionally** — threw
   `[Bill] SERVICE NOT FOUND: IEventBus` + a `NullReferenceException` at `GunFeedback.cs:25` on first Play,
   because `GunFeedback` lives on a `DontDestroyOnLoad` object present before `BillBootstrap` finishes
   registering services. Fixed by copying the exact poll pattern already used by `PlayerSpawnManager`/
   `CombatSession` in this codebase (`TrySubscribe()` called from both `OnEnable` and `Update` until
   `Bill.IsReady`), rather than the docs' `GameReadyEvent`-subscribe pattern, since the poll pattern is what's
   proven to work here.
3. **Wrapper prefab's own `HitscanGun._config` was never wired** — only `_muzzle` had been set when the
   prefab was created; `GunConfig` was null until fixed via `manage_prefabs(action="modify_contents")`,
   confirmed by `gun.Config == null` / `Ammo == 0` before the fix, `Config == AK74_GunConfig` / `Ammo == 30`
   after.

**Head hit** (same target, aimed at feet+1.68m — above the `HeadZoneMinHeight = 1.5f` constant):
```
fired=True hitPart=Head heightAboveFeet=1.557953
```

**Ammo delta = exactly 1 per accepted shot**, confirmed across 11 total accepted shots this session (two Play
sessions): `30→29→28→27` (session A) and `30→29→28→27→26→25→24` (session B, fresh `_localShotCounter`).

**ShotId uniqueness**: strictly incrementing per session — session A: `1, 2, 3`; session B: `1, 2, 3, 4, 5, 6`.
`_localShotCounter` is a per-instance field, so a fresh Play session naturally restarts at 1 — this is correct
per the telemetry contract (dedupe key is `(shooter, shotId)`, not `shotId` alone).

**Verify-recipe note**: the task's own recipe calls for 20 shots across three target types in one continuous
Play session. This session fired 11 accepted shots total (world ×9, body ×1, head ×1) across two Play
sessions plus a fire-rate-gate stress test (below) — full mechanical coverage of all three target types and
the ammo/shotId contract, but short of a single unbroken 20-shot pass. Recommend a follow-up human Play Mode
pass (or a longer automated run) before treating Test Round 1 evidence as final; the mechanism itself is
proven correct and repeatable.

## 3. 1.1.2 — fire gate, magazine, simplified reload

Acceptance: *"RPM trong tolerance đã ghi; ammo không âm; reload không tạo shot; round freeze chặn fire."*

**Fire-rate gate** (5 `TryFire()` calls issued back-to-back within the same execute_code call, i.e. same
engine frame / same `Time.unscaledTime`):
```
successes(of 5 rapid calls same frame)=1 ammo now=27 lastShotId=3
```
Only the first call fired; the other 4 were correctly rejected by the `Time.unscaledTime < _nextFireAllowedAt`
gate — matches `roundsPerMinute = 600` → `FireIntervalSeconds = 0.1s`, no double-fire within one frame.

**Empty-magazine dry-fire + auto-reload** (ammo forced to 0 via reflection to avoid spending ~24 real
fire-rate-gated round trips just to drain the mag — the GATE logic itself was already proven above):
```
ammoForced=0
TryFire()=False dryFireEventReceived=True stateAfter=Reloading
```
`GunDryFireEvent` fired, no shot registered (`TryFire` returned `false`), state auto-transitioned to
`Reloading` — matches GDD's "hết đạn thì súng tự nạp, không cần làm gì" safety net.

**Reload completes and refills exactly to magazine size** (~2s later, `reloadSeconds = 1.8f`):
```
state=Ready ammo=30
```

**Round-freeze gate**: `GunInput.Update()` sets `gun.MatchPhaseAllowsFire = ArenaManager.Instance == null ||
Phase == Playing` every frame; `Gun.TryFire()` returns `false` immediately if `!MatchPhaseAllowsFire`. Not
independently exercised this session (would need `ArenaManager` in `Warmup`/`RoundEnd`, which `01_TOSSZONE_Main`
doesn't have) — logic reviewed, not Play-Mode-proven. Flagged for the 02_FPSMAP two-client pass.

## 4. 1.1.3 — immediate local feedback

Acceptance: *"feedback không phụ thuộc network callback; miss vẫn có tracer/impact phù hợp; pool reuse không
để stale visual."*

- `GunFiredEvent` fires synchronously inside `Gun.TryFire()`, same call stack as the raycast/ammo decrement —
  no RPC/network hop in the path at all for `1.1.x` (network relay is task `1.2.2`, not built yet). This
  structurally satisfies "local feedback doesn't wait on network" by construction, not just by observation.
- `GunFeedback.OnFired` ran on every one of the 11 accepted shots above with **zero exceptions** in the
  console (checked after each Play session) — muzzle-flash pool spawn, tracer pool spawn + `Init`, and (for
  the two non-World hits) `ImpactBurst.Show` all executed without error.
- Audio: `Bill.Audio.PlayPitched`/`Play` calls ran but only produced `[Bill.Audio] No AudioLibrary set.`
  warnings — there is **no AudioLibrary configured in this project at all** (pre-existing gap, not introduced
  by this work); the call sites are correct and will work once an AudioLibrary + gun SFX clips exist.
- **Not verified this session**: visual quality of the tracer/muzzle flash/haptic (no screenshot with the gun
  clearly in frame — the XR Device Simulator's default camera angle didn't line up with the wrist in the one
  screenshot attempt; haptics need a real controller). Pool-reuse-leaves-no-stale-visual is true by
  construction (`TracerFx.OnReturnedToPool` calls `BillTween.KillTarget(this)` per the S15 lesson) but not
  independently observed across many reuse cycles.
